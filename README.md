# MicroTwin NoiseLab

MicroTwin NoiseLab 帮助存算一体芯片研发团队判断误差从哪里来，以及下一轮实验该改什么。比如，在相同的写入脉冲预算下，优先修正电导偏差最大的单元，还是优先修正对推理输出影响最大的单元？平台可以用同一份目标矩阵和留出输入比较两种方案。

## 可以做哪些实验

| 工程问题 | 对应实验 |
| --- | --- |
| 同一个器件反复读，波动有多大？ | 对照 TaOx 实测记录的频谱与时间相关性，分析读噪声 |
| 哪些单元值得再补写一次？ | 设置目标电导矩阵，跟踪每轮写入脉冲、批量回读和半选扰动 |
| 读出误差来自哪里？ | 比较阵列线阻、TIA 建立时间、ADC 量程与采样时刻的影响 |
| 补偿参数能否用于另一颗芯片？ | 导入 CSV，按温度或芯片留出数据，检查补偿后的误差 |
| 器件噪声怎样传到模型输出？ | 对 Qwen3-8B 和小型 Llama 架构模型回放噪声，查看已有评估结果 |
| 系统瓶颈在哪里？ | 在同一 Transformer 层的请求轨迹上比较 GPU、HBM 和 HBF 配置 |

教学图解、物理仿真、公开实测数据和模型回放各有适用范围。阅读结果时请查看实验页中的数据来源、单位、基线和模型假设。

## 本地运行

将完整站点文件解压到同一目录，保留子目录结构。在含有 `index.html` 的目录中运行：

```sh
python -m http.server 8000
```

在浏览器打开 `http://localhost:8000/`。中文首页为 `index.html`，英文首页为 `en.html`。首次使用可以先读 `cim-guide.html`，然后在 `parallel-write.html` 比较写入策略。

## 发布到 GitHub Pages

1. 将发布包解压后的文件提交到 `main` 分支根目录，确认 `index.html` 和 `.nojekyll` 都在根目录。
2. 打开仓库 **Settings → Pages**。选择 **Deploy from a branch**、**main**、**/ (root)**，点击 **Save**。
3. 等待部署完成，在 Pages 设置中复制 **Visit site** 对应的网址。
4. 用未登录 GitHub 的浏览器打开该网址，切换一次实验参数，下载并打开 `read-window.csv`。面向中国大陆客户交付时，再用目标移动网络或办公网络验证一遍。

本仓库包含完整发布文件后即可托管静态站点。单独提交本 README 只会建立项目说明页。
